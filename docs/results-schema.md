# Results schema

Each planned job writes `jobs/<run_id>/result.json` atomically. A failure still writes a record. The campaign's atomic `manifest.json` records the normalized config, every planned job fingerprint, and every planned instance. Resume requires that manifest to match; individual result files mark completed jobs.

| Field | Meaning |
| --- | --- |
| `run_id` | Stable identifier derived from all model and solve inputs, including mode, its effective time limit, solver variant, and full solver options |
| `benchmark`, `instance_id`, `instance_params`, `seed` | Instance inputs; the ID is a family prefix plus twelve content-hash hex digits; generation rejects a truncated-hash collision |
| `strategy`, `transformation`, `transformation_options` | Display label, registered Pyomo transformation name, and explicit options |
| `solver`, `subsolver`, `variant`, `mode`, `time_limit` | GAMS interface, selected solver, solver option variant, job mode, and mode-specific limit |
| `concurrency` | Effective `--jobs` value for the invocation that produced the record; null in older records |
| `duration_sec` | Wall-clock duration for the complete job, including model construction, transformation, solve, and result extraction |
| `solver_time_sec` | GAMS `ETSOLVE` reported by Pyomo as solver user time; performance profiles use this field |
| `transform_sec` | Wall time for logical and GDP transformations, structural counting, and mode relaxation |
| `m_estimation_time_sec`, `m_estimation_subsolves` | Time and GAMS/Gurobi subsolve count spent by this job estimating multiple-Big-M values; zero on a cache hit and null for other strategies |
| `m_estimation_time_total_sec`, `m_estimation_cache_hit` | Published per-instance M-estimation cost and whether this row loaded an existing cache; the total is copied from `mbigm/<instance_id>.json` on a hit and is null for other strategies |
| `status` | `optimal`, `globally_optimal`, `locally_optimal`, `feasible`, `timeout`, `node_limit`, `infeasible`, `solver_error`, `build_error`, or `transform_error` |
| `objective`, `lower_bound`, `upper_bound`, `abs_gap`, `rel_gap` | Objective and bound data when available |
| `num_variables`, `num_constraints`, `num_nonzeros`, `num_discrete_variables` | GAMS model statistics returned through GDX |
| `presolved_num_variables`, `presolved_num_constraints`, `presolved_num_nonzeros` | Solver-log presolved-model size, null when not printed |
| `presolved_num_soc`, `presolved_num_bilinear`, `presolved_num_quadratic`, `presolved_num_nonlinear` | Recognized post-presolve conic, bilinear, quadratic, and nonlinear constraint counts when printed |
| `n_cone_rows`, `n_fallback_rows`, `n_equality_fallback_rows`, `n_epigraph_vars` | CEHR emitter paths; GEHR reports homogenized rows in `n_fallback_rows`; unrelated transformations use null |
| `n_quadratic_terms`, `n_bilinear_binary_terms`, `n_binary_square_terms` | Canonical active transformed monomial counts before integrality relaxation: each distinct degree-two-or-higher variable-factor monomial with a nonzero merged coefficient is counted once, then classified as pure, containing a binary factor, or containing a repeated binary factor. Algebraically repeated orderings are coefficient-merged, so exact cancellations disappear. Quotient numerators with the same canonical denominator combine within one boundary; different denominator boundaries do not cross. A matching enclosing denominator contributes its variable factor to a combined nonlinear numerator, while linear numerator terms remain linear. Non-polynomial intrinsics remain opaque collection boundaries. |
| `n_disaggregated_vars`, `n_nonlinear_constraints` | Transformed disaggregated-variable and active nonlinear-constraint counts |
| `solver_status`, `termination` | Pyomo solver status and termination condition strings |
| `solution` | Benchmark payload plus original numeric variables under `variables`, Boolean variables under `booleans`, and disjunct indicators under `indicators` |
| `timestamp` | UTC completion timestamp |
| `versions` | Python, Pyomo, GAMS, subsolver, and Git revision information; subsolver version is parsed from the retained log |
| `error` | Failure details, otherwise null |

Ground truth is selected per instance. A `status="certified"` reference takes precedence; an instance without one uses the best finite population objective among feasibility-verified `optimal` and `globally_optimal` solve records, excluding every `variant="convex"` record. `ground_truth_source` is therefore `reference`, `population-fallback`, or `unknown` per instance. Correctness uses `abs(value - truth) <= max(atol, rtol * abs(truth))` and requires a verification row. Only agreement with certified reference truth can return `correct=true`. Population fallback can refute a verified-optimal claim whose objective is strictly worse beyond tolerance, returning false, but agreement with fallback remains unknown and never counts as solved. `invalid_certificate` applies only to solve records and flags an optimality claim whose dual bound exceeds a certified reference beyond tolerance. `negative_control` is true only for convex-variant GEHR and binary-multiplication rows.

The `solve` mode runs the complete transformed MINLP and is the only mode used for ground truth and summaries. The `root` mode stops after root-node processing. A clean root termination reported as optimal or globally optimal is accepted at the configured relative-gap tolerance (`1e-6`), rather than requiring numerical zero. Solver-log node-limit markers identify `node_limit` whether or not a finite bound was returned. The `relaxation` mode applies `core.relax_integer_vars`; a nonzero discrete-variable count is a `transform_error`. Bounds come from GDX with solver-log parsing as a missing-value fallback. Non-finite values and solver infinity sentinels are null.

Reports identify a method by `(strategy, solver, subsolver, variant)`. They create a separate profile for each solver, subsolver, variant, and requested mode and use strategies as curves; timings from different solvers are never pooled.

`exact-hull report` writes `results.csv` (or `results.xlsx`), `summary.csv`, `methods.csv`, `bounds.csv`, `verification.csv`, and `censoring.csv`. `summary.csv` contains per-status counts and median observed solver time. `methods.csv` has one row per planned solve method, including methods with no records, and reports confirmed solved count, planned denominator, invalid-certificate count, unknown-reference count, the per-instance-deduplicated `m_estimation_time_total_sec`, and a shifted geometric mean with shift 10 seconds. The shifted mean charges the full time limit unless a solve is confirmed against certified reference truth and is feasibility-verified. M-estimation time is excluded from charged time and the SGM. Because the instance total is repeated on every mbigm row, aggregate it by unique `instance_id` (or use the already deduplicated methods field), never by summing raw rows. Solve-mode performance-profile cells require reference-certified correctness, so population-fallback instances remain unsolved there. Root-mode cells require `root_bound_valid`; relaxation-mode cells require `relaxation_certified`. The root gate may use verified-feasible fallback truth only to exclude inconsistent bounds. The bounds table combines modes and surfaces path/structure counts. `relaxation_certified` requires an acceptable termination, finite primal and dual values, and their agreement. `relaxation_gap` is null otherwise. Every root-bound consumer applies the same finite/status/reference-consistency gate, so a bound above the available truth is excluded from gaps, gap-closed values, and profiles. `censoring.csv` counts exclusions by method and reason.

`root_gap_closed = (root_bound_arm - root_bound_bigm) / (reference - root_bound_bigm)`. It is reported only when both root bounds pass the gate and the denominator exceeds `1e-6 * max(1, abs(reference))`. On GEHR rows, `relaxation_matches_cehr` compares only certified relaxations.

`eps_relaxation.toml` shares `random_psd.toml`'s instances and seed. Its gaps are available when a compatible `references.json` is present; otherwise join its `bounds.csv` with the `random_psd` campaign by `instance_id`.
